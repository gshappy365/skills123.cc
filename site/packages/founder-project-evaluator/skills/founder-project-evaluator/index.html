00 · 核心判断

先判决，再谈增长

Founder Project Evaluator 把创业评估从“这个想法听起来不错吗”改成“现阶段有什么可证伪的证据”。

它适合评估创业 Idea、MVP、Launch 或 Scale readiness，也适合在决定继续、暂停或终止一个项目之前做一次结构化 Gate Review。

每次评估都必须先说清楚当前阶段和最大风险，再列出最强证据、最大反证、本轮主动攻击路径、缺失证据和下一步动作。没有定量证据时，明确写出“无定量证据”，不把愿景、访谈感受或漂亮的叙事包装成进展。

第一句给出阶段判决，第二句指出最大风险；优点不能替代证据。

— Founder Project Evaluator 的首要规则

01 · 阶段诊断

项目现在到底处在哪个阶段

阶段判断决定评分口径，也决定什么样的证据才足以进入下一步。

IDEA

验证问题与方案

主要还是假设，真实使用和付费证据很少。

MVP

测试真实行为

原型或服务已经被使用，正在验证真实反馈。

LAUNCH

开始重复发生

付费、留存、渠道或运营开始出现可重复信号。

SCALE

增长稳定扩张

组织、GTM 和护城河成为主要瓶颈。

不清楚时选择更早阶段，采用 fail-closed 偏差。不要因为团队讲得更完整，就把项目自动升级到更成熟的阶段。

02 · 证据评分

五个维度，合计 10 分

每个维度只看可检查的事实：0 分是没有证据，1 分是初步证据，2 分是支持下一步的清晰证据。

0–2问题与需求
0–2产品行为
0–2留存与付费
0–2渠道与成本
0–2阶段风险
证据类型更有用的事实不合格的说法
用户/需求访谈中重复出现的问题、行为数据或明确的付费动作“用户都很喜欢”
留存按 cohort 观察的 30/90 天留存和回访行为“有很多注册用户”
单位经济CAC、毛利、回收周期和服务成本“规模大了就会盈利”
渠道可重复获客路径、转化率和渠道依赖“可以靠社媒传播”

03 · 主动证伪

主动攻击这个项目为什么可能失败

每个 Gate 必须包含最大反证，以及本轮真实执行过的推翻路径。

最大反证

写出最强的失败理由，而且要具体到一个可以被数据或行动推翻的事实。

价值主张攻击

尝试让竞品替代、用户拒绝、渠道失效或服务成本失控，观察主张是否仍站得住。

竞争偷走路径

如果现有平台复制核心功能，项目还剩什么不可替代的优势和证据？

单位经济断裂

把获客、交付、支持和留存放在同一张表里，寻找规模越大亏损越快的环节。

薄输入也要先给 Gate，不先发一轮问题清单来拖延判断。未知项进入“缺失证据”，下一步动作必须能产生可观察结果。

04 · 输出 Gate

让判决可以被复核

最终输出不是一篇项目介绍，而是一份可以继续验证、也可以被推翻的判断记录。

Idea → MVP

总分低于 8：禁止进入 MVP。

MVP → Launch

0–4 停留；5–7 小步推进并补证据；8–10 进入下一阶段。

Launch → Scale

总分低于 8：禁止进入 Scale，只能强化 Launch 系统。

任何阶段

先写判决和最大风险，再写证据、反证和三个动作。

# Gate Review ## 判决 Decision [阶段判决] [最大风险] ## 当前阶段 Stage Idea / MVP / Launch / Scale ## 阶段评分 Score __/10 ## 最大反证 Strongest counter-case [最强失败理由] ## 下一步 3 个动作 Next 3 actions 1. [可观察结果 + 时间盒] 2. [可观察结果 + 时间盒] 3. [可观察结果 + 时间盒]
  • 不要把愿景包装成证据。
  • 不要在缺少证据时承诺进入下一阶段。
  • 涉及投资、医疗、法律或重大财务决策时，继续做人工核验。
