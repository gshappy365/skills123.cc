沙箱提供者（Sandbox providers）| Sandcastle 文档 | AI Hero

run()、interactive() 和 createSandbox() 上的 sandbox 选项可以接受任何沙箱提供程序（sandbox provider），包括 noSandbox()：选择让代理直接运行……

run()、interactive() 和 createSandbox() 的 sandbox 选项可以接受任何 sandbox provider，包括 noSandbox()：当你不想要隔离时，可以选择让 agent 直接运行在 host 上。内置 provider 如下：

Provider 导入路径 类型 可用于
Bubblewrap @ai-hero/sandcastle/sandboxes/bwrap 原生（bind-mount） run(), createSandbox()
Seatbelt @ai-hero/sandcastle/sandboxes/seatbelt 原生（bind-mount） run(), createSandbox()
Docker @ai-hero/sandcastle/sandboxes/docker Bind-mount run(), createSandbox(), interactive()
Podman @ai-hero/sandcastle/sandboxes/podman Bind-mount run(), createSandbox(), interactive()
E2B @ai-hero/sandcastle/sandboxes/e2b 隔离 run(), createSandbox()
Modal @ai-hero/sandcastle/sandboxes/modal 隔离 run(), createSandbox()
Sprites @ai-hero/sandcastle/sandboxes/sprites 隔离 run(), createSandbox()
Vercel @ai-hero/sandcastle/sandboxes/vercel 隔离 run(), createSandbox(), interactive()
No-sandbox @ai-hero/sandcastle/sandboxes/no-sandbox 无 run(), createSandbox(), interactive()

Worktree 方法（wt.run()、wt.interactive()、wt.createSandbox()）接受的 provider 与对应的顶层方法相同。wt.interactive() 在未指定 sandbox 时默认使用 noSandbox()。

import { run, interactive, claudeCode } from "@ai-hero/sandcastle";
import { bwrap } from "@ai-hero/sandcastle/sandboxes/bwrap";
import { seatbelt } from "@ai-hero/sandcastle/sandboxes/seatbelt";
import { docker } from "@ai-hero/sandcastle/sandboxes/docker";
import { noSandbox } from "@ai-hero/sandcastle/sandboxes/no-sandbox";
// 为当前操作系统选择原生 sandbox，这样一个 main.ts 就能同时在 macOS 和 Linux 上工作：
const sandbox = process.platform === "darwin" ? seatbelt() : bwrap();
// 原生、Docker、Podman 和 Vercel provider 在 run() 和 createSandbox() 中可以互换：
await run({
agent: claudeCode("claude-opus-4-8"),
sandbox,
prompt: "...",
});
// No-sandbox 让 agent 直接运行在 host 上，可被 run()、
// createSandbox() 和 interactive() 接受。完全跳过隔离：
await interactive({
agent: claudeCode("claude-opus-4-8"),
sandbox: noSandbox(),
prompt: "...", // 可选：省略则启动不带初始 prompt 的 TUI
cwd: "/path/to/other-repo", // 可选：默认为 process.cwd()
});

你还可以使用 createBindMountSandboxProvider 或 createIsolatedSandboxProvider 来创建自己的 provider。

原生 sandbox 使用操作系统自带的进程 sandbox 而非容器来约束 agent：Linux 和 WSL2 上是 Bubblewrap，macOS 上是 Seatbelt。不需要构建镜像，也没有 daemon 需要运行。每次 exec 都是一个全新的 sandbox 进程，只读地使用你 host 上自己的工具。

  • 文件。 agent 只能写入仓库（或它的 worktree）、Sandcastle 挂载的 git 目录、一个私有的临时目录和一个私有的 home 目录。你的 home 目录、SSH 密钥、agent 登录凭据和其他仓库都被隐藏。仓库以它真实的 host 路径出现，就像在 noSandbox() 下一样。
  • 工具链。 host 上 PATH 里的每个目录都可读，包括其中每个可执行文件符号链接指向的安装根目录，所以 ~/.local/bin 里的 claude 或 nvm 安装的 codex 都能直接使用。安装根目录在可执行文件安装于某个 node_modules 目录下时指的是该包本身，否则只是可执行文件所在的目录，因此 npm link 的检出目录不会被暴露。等于你的 home 目录或其祖先目录的 PATH 条目，以及含有 .git 的安装根目录，永远不会被挂载。其他路径可用 mounts 添加。
  • 登录凭据。 每个 sandbox 都有一个全新的私有 home 目录，关闭时会被删除，所以 agent 无法使用你 home 目录中存储的登录凭据：~/.claude、~/.codex、~/.config/gh。seatbelt() 并不保证让 agent 无法访问你的 macOS 钥匙串（Keychain），所以别指望它做到这一点。把 agent 的登录凭据放在 .sandcastle/.env 中（CLAUDE_CODE_OAUTH_TOKEN、ANTHROPIC_API_KEY 等），并为 gh 配置 GH_TOKEN。你的 git 身份信息仍会被复制进去，所以提交会带上你的名字。
  • 环境变量。 agent 只能看到 Sandcastle 传入的环境变量，外加 PATH、HOME 和 TMPDIR。
  • 进程。 agent 无法向你的进程发送信号，它启动的每个进程都会在 sandbox 关闭时被杀掉。在 seatbelt() 下，离开自己进程组的进程（通过调用 setsid 或 setpgid）是个例外：参见隔离控制。
  • 网络。 开放的，包括你 host 的 localhost。
  • 不支持 root。 带 sudo: true 的 exec 和 hook 会被拒绝，并提示使用 docker()。没有镜像可以安装系统包，所以请安装在你自己的 host 上。
  • 不支持 interactive()。 原生 provider 配合 interactive() 会抛出 NativeInteractiveNotSupportedError。请使用 run()，或者给 interactive() 传 docker() 或 noSandbox()。

两者都接受同一组少量选项：

bwrap({
env: { MY_VAR: "value" }, // 启动时合并，类似 docker() 的 env
mounts: [
// 每个路径在 sandbox 内都以它真实的 host 路径出现，所以
// sandboxPath 必须等于 hostPath。readonly 默认为 false。
{ hostPath: "/opt/my-tool-cache", sandboxPath: "/opt/my-tool-cache" },
{
hostPath: "/home/me/shared-config",
sandboxPath: "/home/me/shared-config",
readonly: true,
},
],
maxOutputTailChars: 65_536, // 与 docker() 相同
});

构造原生 provider 时，会（每个进程一次）检查你的机器能否运行它。如果不能，会抛出 NativeSandboxUnavailableError，如果存在可执行的修复命令，还会附带一个 fixCommand。它会在任何 worktree 创建之前抛出，并且绝不会回退到不加 sandbox 运行 agent。

import { NativeSandboxUnavailableError } from "@ai-hero/sandcastle";
try {
bwrap();
} catch (error) {
if (error instanceof NativeSandboxUnavailableError) {
console.error(error.message); // 用平实的语言说明原因
console.error(error.fixCommand); // 例如 "sudo apt install bubblewrap"，或 undefined
}
}

Linux 上的 bwrap()。 它需要 bwrap 在 PATH 上；如果缺失，错误信息会给出你的发行版的安装命令。Ubuntu 24.04 及更高版本通过 AppArmor 阻止了 Bubblewrap 所需的非特权用户命名空间。错误信息会说明这一点，其 fixCommand 会给 bwrap 一个允许用户命名空间的 AppArmor profile：

printf 'abi <abi/4.0>,\ninclude <tunables/global>\nprofile bwrap %s flags=(unconfined) {\n  userns,\n}\n' "$(command -v bwrap)" \
| sudo tee /etc/apparmor.d/bwrap >/dev/null && sudo apparmor_parser -r /etc/apparmor.d/bwrap

或者，更粗暴地，为所有程序允许用户命名空间：sudo sysctl -w kernel.apparmor_restrict_unprivileged_userns=0。

Windows 上的 bwrap()。 在 WSL2 中运行 Sandcastle 并使用 bwrap()，仓库要放在 Linux 文件系统上（例如 ext4，如 ~/code/my-repo），不要放在 /mnt/c 下。在 sandbox 内部，/mnt、/run/WSL 和 WSL_INTEROP 是隐藏的，所以 agent 无法运行 Windows 的 .exe。

macOS 上的 seatbelt()。 它需要 macOS 14 或更高版本，运行系统的 /usr/bin/sandbox-exec，所以无需安装任何东西。macOS 拒绝嵌套 Seatbelt sandbox，所以 seatbelt() 无法在另一个 Seatbelt sandbox 内启动；错误信息会说明这一点。

Agent 自带的 sandbox。 原生 sandbox 是隔离控制层，而 Sandcastle 已经在运行 agent 时跳过了它们的权限检查，所以请关掉 agent 自己的 sandbox 功能。agent 无法在 seatbelt() 内应用它自己的 Seatbelt sandbox，因为 macOS 拒绝嵌套。在 bwrap() 内，agent 自己的 Bubblewrap sandbox 能否启动取决于你的内核。

e2b() 在 E2B sandbox 中运行 agent，这是一个 Firecracker microVM。安装 SDK（npm install e2b；它需要 Node 22.19 或更高版本）并在 shell 中设置 E2B_API_KEY，或者传入 apiKey 选项。不要把密钥放在 .sandcastle/.env 里：在那里声明的密钥会被转发进 sandbox。

E2B 的默认模板没有 agent CLI。它的预构建 claude 和 codex 模板自带一个：

import { run, claudeCode } from "@ai-hero/sandcastle";
import { e2b } from "@ai-hero/sandcastle/sandboxes/e2b";
await run({
agent: claudeCode("claude-opus-4-8"),
sandbox: e2b({ template: "claude" }),
prompt: "...",
});

e2b() 接受 SDK 的 Sandbox.create() 选项（template、timeoutMs、apiKey、metadata、network 等），但 envs 和 lifecycle 除外，它们由 provider 设置。仓库会落在 $HOME/workspace。每个 sandbox 会在 close() 时被杀掉，或者在 timeoutMs（默认 30 分钟）超时后被杀掉，所以超时设置必须覆盖环境准备、agent 运行以及同步提交回来的时间。E2B 免费的 Hobby 套餐将单个 sandbox 限制在 1 小时。句柄的 sandboxId 就是 E2B 的 sandbox id。interactive() 暂不支持。

sprites() 在一个新的 Fly.io Sprite 中运行每个 sandbox，这是一个 Linux microVM。它是一个隔离 provider：Sandcastle 把仓库复制到 /home/sprite/workspace，再把 agent 的提交带出来。在 Sandcastle 旁边安装 SDK：

npm install @fly/sprites
  • 认证。 把 Sprites token 放在 SPRITES_TOKEN 中（.sandcastle/.env 或你的 shell 里）。Sprites CLI 使用的 SPRITE_TOKEN 也可以。token 选项的优先级高于这两者。
  • Node 24。 @fly/sprites 要求 host 上的 Node 为 24 或更高版本。
  • 镜像。 Sprites 只有一个基础镜像，已预装 git、Node 和 claude CLI。其他 agent 的 CLI 可在 onSandboxReady hook 中安装。
  • 销毁。 Sprite 会一直运行直到被删除。close() 会删除它，设置失败时也会删除。如果进程被中断（SIGINT/SIGTERM）或在没有关闭 sandbox 的情况下退出，Sandcastle 会通过一个后台进程删除 Sprite。
  • sandboxId 是 Sprite 的名称，Sprites CLI 和 API 都接受它。
  • sudo: true 使用 Sprite 自带的无密码 sudo。
  • 不支持 interactive()。 请使用 run() 或 createSandbox()。
import { run, claudeCode } from "@ai-hero/sandcastle";
import { sprites } from "@ai-hero/sandcastle/sandboxes/sprites";
await run({
agent: claudeCode("claude-opus-4-8"),
sandbox: sprites({
env: { MY_VAR: "value" }, // 启动时合并，类似 docker() 的 env
}),
prompt: "...",
});

modal() 在 Modal sandbox 中运行 agent。安装 SDK（一个可选的 peer dependency），并提供一个 Modal token：MODAL_TOKEN_ID 和 MODAL_TOKEN_SECRET（来自 modal token new 或控制台），或者用 tokenId 和 tokenSecret 选项，它们的优先级更高。两者都没有时，SDK 会读取 ~/.modal.toml。

npm install modal

import { run, claudeCode } from "@ai-hero/sandcastle";
import { modal } from "@ai-hero/sandcastle/sandboxes/modal";
await run({
agent: claudeCode("claude-opus-4-8"),
sandbox: modal(),
prompt: "...",
});
  • 镜像。 Modal 没有默认镜像，所以 modal() 会构建一个：node:24-bookworm（Node LTS、git、tar）并安装 Claude Code。Modal 只构建一次并缓存它。传 image 可以使用你自己的：可以是 registry 标签（如 "node:24-bookworm"），或者一个 Modal Image。它需要 sh 和 git；其他 agent 的 CLI 可以安装在里面，或在 onSandboxReady hook 中安装。
  • Root。 Modal 无论镜像的 USER 是什么，都以 root 身份运行所有命令，所以 sudo: true 没有实际作用。modal() 会设置 IS_SANDBOX=1，这是 Claude Code 以 root 身份跳过权限检查所必需的。
  • 生命周期。 一个 sandbox 最长存活 timeoutMs，默认一小时（Modal 自己的默认是 5 分钟，上限是 24 小时）。Modal 无法在创建后延长它，所以要把它设置得比你的最长运行时间更长。close() 会终止 sandbox。
  • 其他选项。 sandbox 会放在由 appName（默认 "sandcastle"）命名的 Modal App 中，不存在时会自动创建。create 会透传其他 sandboxes.create() 选项，比如 cpu、memoryMiB 和 regions。
  • sandboxId 是 Modal 的 sandbox id（sb-…）。可以使用 modal SDK 的 modal.sandboxes.fromId(<sandboxId>) 重新连接，然后调用 terminate()。某些账号的 sandbox 不会出现在 sandboxes.list() 中，所以要保留 id。
  • Host。 modal SDK 需要 Node 22 或更高版本。

sandbox 能保护你免受什么威胁取决于 provider。原生 sandbox 是为意外事故和提示注入（prompt-injection）攻击而设计的：一个运行了错误命令、或者遵循了植入在 issue 或网页中指令的 agent，无法读取你的凭据、无法在仓库之外写入，也无法触碰你的其他进程。

它们不能防范：

  • 内核逃逸。 原生 sandbox 是共享内核的进程 sandbox。在 Linux 上，bwrap() 的强度大致相当于 runc 容器（Linux 上的 Docker）。在 macOS 上，seatbelt() 弱于 Docker Desktop，后者在 VM 中运行容器。
  • host localhost 上的服务。 网络是开放的，sandbox 可以访问监听在 127.0.0.1 上的任何东西，比如开发服务器或本地数据库。
  • macOS 上的进程列表。 Seatbelt 没有 PID namespace。agent 无法向你的进程发送信号，ps、pgrep 和进程列表 sysctl 都被阻止了，但你的进程不会像在 bwrap() 自己的 PID namespace 中那样被隐藏。sandbox 之外的路径可以作为元数据被看到：agent 可以检查某个路径是否存在，读取它的大小和时间戳，但不能读取其内容。
  • macOS 上的脱离进程。 seatbelt() 会杀掉每次 exec 的进程组。一个通过调用 setsid 或 setpgid 离开该组的进程，会在 close() 之后以及你的 Node 进程被杀掉之后继续存活。它仍然处于 Seatbelt profile 的约束之下，所以它仍可以写入 worktree 并访问网络，直到它退出或你手动杀掉它。

如果需要基于镜像的 sandbox，或者在 macOS 和 Windows 上获得 VM 边界，请使用 docker() 或 podman()。如果需要比共享内核更强的隔离，请使用 vercel() 这类远程 provider，它把 agent 运行在自己独立的 Firecracker microVM 中。

基于镜像的 provider（docker()、podman()）在一个由配置目录（sandcastle init 在你仓库中创建的 .sandcastle/ 文件夹）构建的镜像中运行 agent。修改 Dockerfile 或 Containerfile 之后，用 build-image（构建镜像的 CLI 命令）重建镜像；不再需要时，用 remove-image 删除它：参见 sandcastle docker build-image 及其后的命令。原生 provider 没有镜像。

Sandcastle 自带内置 provider（见上表），但你也可以创建自己的。有两种类型：

  • Bind-mount —— sandbox 可以挂载 host 目录。Sandcastle 在 host 上创建一个 worktree，provider 把它挂载进去。不需要文件同步。适用于 Docker、Podman 或任何本地容器运行时。
  • Isolated —— sandbox 有自己的文件系统（例如云端 VM）。provider 通过 copyIn 和 copyFileOut 处理代码的进出同步。适用于 sandbox 无法访问 host 文件系统的场景。

沙箱句柄（sandbox handle）契约

两种 provider 类型的 create() 函数都会返回一个沙箱句柄。该句柄暴露以下内容：

方法 是否必需 描述
exec 两者都需要 运行命令，可选通过 options.onLine 逐行流式输出 stdout
close 两者都需要 销毁沙箱
copyFileIn Bind-mount 把单个文件从宿主机复制进沙箱
copyFileOut 两者都需要 把单个文件从沙箱复制到宿主机
copyIn Isolated 把文件或目录从宿主机复制进沙箱
worktreePath 两者都需要 沙箱内仓库目录的绝对路径
sandboxHomedir Bind-mount，可选 沙箱内命令看到的 agent 主目录。默认为 /home/agent
sandboxTmpdir Bind-mount，可选 沙箱内命令看到的可写临时目录。默认为 /tmp
sandboxId 两者都可选 外部工具用来寻址沙箱的 id，例如容器名或厂商沙箱 id。以 Sandbox.sandboxId 的形式暴露

ExecResult

每次 exec 调用都会返回一个 ExecResult：

interface ExecResult {
readonly stdout: string;
readonly stderr: string;
readonly exitCode: number;
}

Docker 和 Podman provider 在命令进程被信号终止时返回 exitCode: 1。数值型退出码会被原样保留，包括表示成功的 0。自定义 provider 也应将信号终止报告为非零退出码。

Bind-mount provider 示例

一个最小化的 bind-mount provider，通过调用本地进程实现（不使用容器）：

import {
createBindMountSandboxProvider,
type BindMountCreateOptions,
type BindMountSandboxHandle,
type ExecResult,
} from "@ai-hero/sandcastle";
import { execFile, spawn } from "node:child_process";
import { copyFile as fsCopyFile, mkdir as fsMkdir } from "node:fs/promises";
import { dirname } from "node:path";
import { createInterface } from "node:readline";
const localProcess = () =>
createBindMountSandboxProvider({
name: "local-process",
create: async (
options: BindMountCreateOptions,
): Promise<BindMountSandboxHandle> => {
const worktreePath = options.worktreePath;
return {
worktreePath,
exec: (
command: string,
opts?: { onLine?: (line: string) => void; cwd?: string },
): Promise<ExecResult> => {
if (opts?.onLine) {
const onLine = opts.onLine;
return new Promise((resolve, reject) => {
const proc = spawn("sh", ["-c", command], {
cwd: opts?.cwd ?? worktreePath,
stdio: ["ignore", "pipe", "pipe"],
});
const stdoutChunks: string[] = [];
const stderrChunks: string[] = [];
const rl = createInterface({ input: proc.stdout! });
rl.on("line", (line) => {
stdoutChunks.push(line);
onLine(line); // 把每一行转发给 Sandcastle
});
proc.stderr!.on("data", (chunk: Buffer) => {
stderrChunks.push(chunk.toString());
});
proc.on("error", (err) => reject(err));
proc.on("close", (code) => {
resolve({
stdout: stdoutChunks.join("\n"),
stderr: stderrChunks.join(""),
exitCode: code ?? 1,
});
});
});
}
return new Promise((resolve, reject) => {
execFile(
"sh",
["-c", command],
{ cwd: opts?.cwd ?? worktreePath, maxBuffer: 10 * 1024 * 1024 },
(error, stdout, stderr) => {
if (error && error.code === undefined) {
reject(new Error(`exec failed: ${error.message}`));
} else {
resolve({
stdout: stdout.toString(),
stderr: stderr.toString(),
exitCode: error
? typeof error.code === "number"
? error.code
: 1
: 0,
});
}
},
);
});
},
copyFileIn: async (hostPath: string, sandboxPath: string) => {
await fsMkdir(dirname(sandboxPath), { recursive: true });
await fsCopyFile(hostPath, sandboxPath);
},
copyFileOut: async (sandboxPath: string, hostPath: string) => {
await fsMkdir(dirname(hostPath), { recursive: true });
await fsCopyFile(sandboxPath, hostPath);
},
close: async () => {
// 本地进程无需销毁任何东西
},
};
},
});

Isolated provider 示例

一个使用临时目录的最小化 isolated provider：

import {
createIsolatedSandboxProvider,
type IsolatedSandboxHandle,
type ExecResult,
} from "@ai-hero/sandcastle";
import { execFile, spawn } from "node:child_process";
import { copyFile, mkdir, mkdtemp, rm } from "node:fs/promises";
import { tmpdir } from "node:os";
import { dirname, join } from "node:path";
import { createInterface } from "node:readline";
const tempDir = () =>
createIsolatedSandboxProvider({
name: "temp-dir",
create: async (): Promise<IsolatedSandboxHandle> => {
const root = await mkdtemp(join(tmpdir(), "sandbox-"));
const worktreePath = join(root, "workspace");
await mkdir(worktreePath, { recursive: true });
return {
worktreePath,
exec: (

stdoutChunks.push(line);
onLine(line);
});
proc.stderr!.on("data", (chunk: Buffer) => {
stderrChunks.push(chunk.toString());

proc.on("error", (err) => reject(err));

},
copyIn: async (hostPath: string, sandboxPath: string) => {
const info = await stat(hostPath);
if (info.isDirectory()) {
await cp(hostPath, sandboxPath, { recursive: true });
} else {
await mkdir(dirname(sandboxPath), { recursive: true });
await copyFile(hostPath, sandboxPath);
}
},
copyFileOut: async (sandboxPath: string, hostPath: string) => {
await mkdir(dirname(hostPath), { recursive: true });
await copyFile(sandboxPath, hostPath);

close: async () => {
await rm(root, { recursive: true, force: true });
},
};
},
});
