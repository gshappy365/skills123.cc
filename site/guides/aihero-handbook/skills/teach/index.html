/teach 技能

teach 会把你运行它的目录变成一个固定的教学工作区，并在多次会话（session）中围绕一个主题持续进行教学

teach 会把你运行它的目录变成一个常设的教学工作区，通过简短、自包含的 HTML 课程，跨越多个会话（session）教你一个主题。

它不会从模型（model）已有的知识出发来教学。它把参数化知识（parametric knowledge）视为不可信的内容。在开始教学之前，它会先找到高可信度的资源，记录到 RESOURCES.md 中，并在每一课里引用它们。它还是有状态（stateful）的。使命、资源、课程以及你的学习记录全部以文件的形式保存在目录里，所以下一个会话从这些文件继续，而不是从上一段对话的残留开始。

你通过输入 /teach 来调用它；智能体（agent）不会主动使用它。

当学习本身就是项目时用它：一门语言、一个框架、你刚加入的代码库、瑜伽、着色器、一份认证考试。它不适合用来随手解释一个问题。

你想要什么 应该用什么
花几周时间学习一个主题，会话内容不断积累 teach
在当前会话里解释一个概念 直接在那个会话里问
智能体上一条消息没讲明白，希望重新解释 wait-what
打磨你已有的思路，而不是学习新材料 grill-me
让一个后台智能体阅读一手资料，留给你一份带引用的文档 research
在拷问过程中冒出了想学的东西，又不想打断拷问 用 handoff 切换到教学工作区，再在那里用 teach

teach 构建的是一个目录而不是单个文件，而且这个技能假设每个工作区只有一个使命，所以要在你愿意完全交给单一主题的地方运行它。别把它放进你正在做的项目里。单独一个仓库是最好的归宿，比全局的 ~/.learnings/ 文件夹或工作项目本身都好。独立的仓库还让你可以提交课程内容，团队之间就是这样共享课程的。

那个目录里会积累的东西：

路径 内容
MISSION.md 你为什么要学这个。其他所有文件都依赖它。如果缺失，teach 做的第一件事就是采访你，直到补上为止
RESOURCES.md 经过审核的教学来源，分为 Knowledge（知识）和 Wisdom（智慧，即社区）两类
lessons/*.html 编号的课程：教学的基本单元
reference/*.html 压缩的速查表、算法、术语表：你会反复回来查阅的文档
learning-records/*.md ADR 风格的笔记，记录你已经确实掌握了什么，用来决定下一步教什么
assets/* 可复用的组件，从一个共享样式表开始，让课程看起来像同一门课
NOTES.md 你明确表达过的教学偏好

关于这个列表有两点说明。术语表适合大多数主题，但这个技能附带的 GLOSSARY-FORMAT.md 已经不再被 SKILL.md 链接，所以只有你主动要求才会有（issue #559）。所有文件都会落在你运行 /teach 的目录里。

理解这个技能的关键词是存储强度（storage strength）：长期记忆留存，与之相对的是流利度（fluency）——那种你正在阅读时感觉自己已经掌握、一周后就忘光的即时回忆。teach 通过合意困难（desirable difficulty）来建立前者：检索练习、间隔、交错。知识先行。在那个阶段，困难对你不利，因为它会消耗你理解内容所需要的工作记忆。然后 teach 通过紧密的反馈循环来操练技能，在那个阶段，困难本身就是工具。

两件事决定了你被教什么。使命（mission）（你想学它的具体的现实原因）是每一课的基础。没有它，课程会变得抽象，也没有任何东西来决定接下来教什么。基于使命和学习记录，teach 会在你的最近发展区（zone of proximal development）内挑选下一课：难到需要花力气，但不至于远到你学不会。

存储强度也是这个技能会反驳你而不是一味附和的原因。一个需要智慧（wisdom）（现实世界的判断力）的问题会先得到一个尝试性的回答，然后被指向一个你可以去验证的社区。这个技能不会让你跳过测验。有用户报告说了一句"非常感谢"，结果被告知操练还没结束。

一课（lesson）就是一个自包含的 HTML 文件，短到一次就能读完，与使命挂钩，给你一个切实可用的收获。它会引用来源，推荐一份值得你自己去读的一手资料，并链接到相邻的课程和参考文档。

你很少会回去重读课程，但你会反复查阅参考文档。所以课程的简短形式（语法表、算法、体式序列、术语表）应该放在 reference/ 里，而不是埋在介绍它的那一课中。

课程由 assets/ 中的组件（components）构建：样式表、测验组件、模拟器、图表辅助工具。复用是默认做法。智能体在编写课程前会先读取 assets/，并基于其中已有的内容来构建。凡是第二课可能用到的组件，它都会写成独立组件，而不是内联在课程里。共享样式表是每个工作区的第一个组件，它让所有课程看起来像同一门课，而不是一堆互不相关的页面。

它把文件放在哪里了？我的出现在了 ~/.claude/skills。 应该在你运行 /teach 的目录里（#377）。

我应该待在同一个会话里，还是每课开一个新会话？ 三种方式都可以：留在同一个会话、在新会话中重新调用 /teach，或者在同一个文件夹里开新会话。每一课都是一次独立的调用。课程状态保存在文件夹里，不在对话里。常见做法是在工作区开一个新会话，然后输入 /teach next lesson for <topic>。

我怎么知道它教的东西不是编造的？ 仅凭这个技能的一面之词，你无法知道。你要去读一手资料。teach 没有可靠到可以不加核验就信任，任何基于 LLM 构建的技能都是如此。它的接地机制（RESOURCES.md、每课里的引用、每课推荐的一份一手资料）让核验课程变得很便宜，但不能免除核验的必要。这种失败确实发生过：一个学二阶魔方的用户收到了编造的、根本无法复原的转动序列。遇到这种情况，检查模型、运行环境（harness）、effort 设置和来源。风险最高的是使用精确记号的程序性领域，最低的是输出可以立即验证的领域，比如可以运行的代码。

测验的正确答案总是第一个选项。 多人在 Sonnet、Opus 和 GLM 上确认了这一点，问题至今未修复。SKILL.md 现在要求所有选项的字数相同。这消除了一条线索（以前正确答案往往是唯一一个推理完整的选项），但对位置无能为力。一位贡献者测试过针对位置的指令级修复，结果在九课中正确答案 33 次里有 33 次落在 A 选项（#335）。所以真正的修复方案是 assets/ 里的一个会打乱选项顺序的测验组件，而不是措辞上的改进。在那之前，别管选项位置。你的 assets/ 目录是你可以随意改动的，所以你可以要求一个在渲染时打乱顺序的组件作为本地修复。

它默认我已经懂了某些东西，用了一些从未定义过的术语。 这是最常见的真实抱怨。这个技能没有评估环节。teach 从使命和学习记录推断你的水平，而第一个会话里还没有学习记录。一位在 wayfinder 管道里运行它的用户说得很直白："它从来没有通过拷问来确认我的起点，所以对我已经懂什么做了大量假设。" 另一位用户报告课程使用了未定义的行话，还有一课讲他的硬件，只讲了硬件能做什么，却从不说它不能做什么。两个办法有帮助：在第一条消息里说明你的已有知识和知识缺口，并在某课讲偏了时当场口头纠正水平，因为纠正本身会变成学习记录，引导下一课。明确的水平评估环节是一个长期存在的功能请求（#725），还不是已发布的行为。

它支持间隔重复吗？它知道什么时候该停止教学吗？ 第一个问题不支持，第二个不可靠。这个技能在课程设计中运用了间隔和交错，但没有任何东西安排复习，也没有 Anki 或日历集成。用户经常同时要求这两个功能。一个相关的缺口是退出标准。正如一位用户所说，teach"擅长生成下一课，但不擅长判断什么时候该停下来转入复习或真正的练习。" 如果你想要复习或操练而不是新材料，就主动开口；这个技能不会自己提出切换。

它只对代码有用吗？ 不是。大部分被报告的使用都在编程之外：韩语、日语敬语、钢琴、吉他、桌游设计、OpenSCAD、电影情节、Azure 和 CCNA 认证、大学考试，还有八岁和十岁的孩子拿到关于密室逃脱和火蝾螈的可打印读物。这个技能里没有任何东西是专门针对编程的。使命、资源、最近发展区和操练在任何领域都以同样的方式运作。在编程领域内，用户报告最大的价值在于熟悉陌生的代码库或新团队的技术栈，比从零学一门语言更有用。

我应该用哪个模型来运行它？ 没有标准答案，而用户报告的差异很大。用户报告更高的推理努力（reasoning effort）设置产出的课程比中等设置更好。一位用户通过 Copilot CLI 用 Codex 跑同一个技能，只得到一张 30 行的 HTML 卡片，而 Claude Code 产出了一整课。它在 Claude Cowork 中可以不加修改地运行，前提是你的组织允许你在那里添加技能。如果课程产出太单薄，先换模型、运行环境（harness）或 effort 设置，再考虑重写你的提示词。

  • 它在空目录里做的第一件事是采访你为什么想学这个，而不是直接生成课程。
  • RESOURCES.md 先填满，课程后跟上，而且每一课都会点出一份值得亲自去读的一手资料。
  • 课程中的论断都带外链。没有引用的课程，说明技能在凭记忆教学。
  • 一课只需一次读完，读完你能做一件以前做不到的事。
  • 在文件夹里开一个新会话并说"下一课"，课程会继续而不是重头开始。
  • learning-records/ 在增长，课程不再重复教你已经展示过掌握的内容。
  • 课程看起来像同一门课：它们链接 assets/ 里的样式表，而不是各自携带一份。
  • 需要判断力的问题会把你指向论坛、subreddit 或课程，而不只是给一个答案。

teach 是一个随时可用的独立技能。它不是构建链中的一环，也不与工程流程共享任何产物；只要你还在学这个主题，它就在自己的目录里工作。

它唯一的真正邻居是 handoff。它们一起回答了"如果我正被拷问一个我不懂的东西该怎么办？" 不要停下拷问去学习。用 /handoff 切换到教学工作区，在那里用 /teach 学会这个主题，然后回去继续之前的拷问。附近的另一个选择是 research，适用于你想要的是一份带引用的文档，而不是课程和记忆留存。当你不确定哪个技能或流程合适时，ask-matt 可以在整个技能集合中为你路由。
