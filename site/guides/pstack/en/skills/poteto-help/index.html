/pstack:poteto-help

Type it yourself

In one lineAsk it "which skill fits this?" and it answers with a prompt you can send as is.

When to use
You're just starting, or you're not sure which skill to use.
Install with
the skills you're asking about
Say it like this
/pstack:poteto-help I want to review this branch. Which skill should I use?

Just asking vs. using it

The same request, typed plainly or with /pstack:poteto-help. Here's what changes.

Just askingWith /pstack:poteto-help
You ask how, and it starts the work, spending tokens.Answers, then hands you a prompt to send when you choose.
Answers from memory with no source.Reads the file it routes to first and links its public GitHub copy.
Hands you a list of skills to run in order.Recommends /pstack:poteto-mode by default. Names one skill only when you want more or less.

Wording worth borrowing

A few sentences from the original: what each one makes the AI do, why it works, and how you can borrow it.

  1. Give the reason behind a ban

    The user asked how, and a pstack run spends real tokens, so let them send the prompt.

    Makes the AI
    When you ask how, it hands you a prompt instead of starting the work and spending your money.
    Why it works
    With the reason attached (you asked how, and a run costs money), the AI can judge edge cases instead of just obeying a rule.
    Borrow it
    When you don't want it to act yet: "Don't change the code, just tell me the plan; I need to check with a colleague first."

  2. Ask a multiple-choice question

    ask one multiple-choice question with these options, then answer only the section they pick

    Makes the AI
    When it can't tell what you need, it asks you one multiple-choice question instead of guessing at length.
    Why it works
    A multiple-choice question takes seconds to answer, and the AI then answers only the part you picked.
    Borrow it
    Add: "If you're unsure what I want, ask me: A short, B detailed, or C with code."

  3. Mention it only when it matters

    Check the state that changes the answer, and mention it only when it does

    Makes the AI
    It reminds you about missing setup only when that changes the answer, instead of nagging every time.
    Why it works
    "Only when it changes the answer" gives reminders an on-off switch, so the AI doesn't dump every check on you.
    Borrow it
    When you ask for a trip plan: "Mention the weather only if it changes the plan."

  4. Fix the opening and the cap

    Lead with the answer. Give at most one example prompt in a code block

    Makes the AI
    The reply opens with the answer and adds at most one example prompt, with no long lead-in.
    Why it works
    Fixing what comes first and a maximum count sets the reply's shape directly, far more concrete than "be concise".
    Borrow it
    Add to your question: "Give the conclusion in the first sentence, and at most one example."

Full text

The SKILL.md the AI reads, as written.

descriptionGuides users through pstack setup, /pstack:poteto-mode, and picking the skill, playbook, or principle for a task. Type /pstack:poteto-help with a question.

Poteto help

Answer the user's question about pstack, hand them a prompt they can send, and link the file the answer came from. For a help question, don't start the work. The user asked how, and a pstack run spends real tokens, so let them send the prompt.

A message that asks for work, such as "use pstack to fix this bug", is not a help question. Read poteto-mode, do the work under it, and mention once that a Custom Mode keeps it on.

This file maps questions to the skills and guide pages that hold the answers. Those files own the details. Read the file you route to before you quote it, and trust it when it disagrees with this map. The links here point into the installed plugin, which the user may not be able to open, so give the user the file's public copy: https://github.com/cursor/plugins/blob/main/pstack/ followed by its path.

Find out what they need

Infer the need from the message and the conversation. A named situation, such as "which skill reviews a PR?", goes straight to its section. If the need is still unclear, ask one multiple-choice question with these options, then answer only the section they pick:

  • Get set up
  • Start a task with /pstack:poteto-mode
  • Pick a skill for a situation
  • Fix a run that went wrong
  • Make pstack my own

Check the state that changes the answer, and mention it only when it does:

  • No pstack settings file (~/.cursor/rules/pstack-models.mdc in Cursor, ~/.claude/rules/pstack-models.md in Claude Code, ~/.agents/pstack-models.md in other harnesses) means /pstack:setup-pstack hasn't run for this user, so every role uses its default model.
  • No verify-* skill or other app harness in the project means agents have no scripted way to drive the app. Mention /pstack:create-verification-skill when the question is about proving a change works.
  • No formal verification skill in the project means no property is checked past what tests reach. Mention /pstack:create-formal-verification-skill when the question is about a race, an invariant, or another case tests rarely hit. When one exists and the code it covers changed after the commit it records as last in sync, mention /pstack:maintain-formal-verification-skill if the question touches that code.

When the model rule is missing and it matters, ask whether the user wants to pick a model for each role and a reasoning budget now. It matters when the user is new, the question is about setup or cost, or the answer depends on which models run. Ask at most once per chat. If the need is also unclear, ask both questions together. Offer two choices:

  • Now: give them /pstack:setup-pstack to type, and answer their question too.
  • Later: answer their question, and add one line saying every role keeps its default model until they run /pstack:setup-pstack.

Get set up

  1. Install with /add-plugin pstack in chat, or from Customize in the sidebar. Outside Cursor, run npx skills add backnotprop/pstack and pick the skills.
  2. Run /pstack:setup-pstack. It asks for a reasoning budget, maps a model to each role, and writes a rule. The rule applies to new chats. Then it offers once each to generate a verification skill and a formal verification skill for the project, unless the project already has one.
  3. Start a real task with /pstack:poteto-mode, a goal, and a check that can pass or fail.

Installing changes nothing until the user invokes a skill. Only /pstack:setup-pstack loads from the user's words. The README and guide page 1 have the details. Offer to word their first prompt with them, per references/prompting.md.

If cost is the worry, say where the tokens go and how to spend fewer. pstack spends extra tokens on subagents and review panels. Rerun /pstack:setup-pstack and pick a smaller budget or cheaper models. A role set to auto or inherit-parent runs on the chat's model, which saves tokens when the chat runs on Auto or a cheaper model. A shorter panel list runs fewer subagents, one for each entry. Save /pstack:poteto-mode for work that needs rigor.

pstack is built for Cursor, and it also installs in Claude Code with /plugin marketplace add cursor/plugins, then /plugin install pstack@cursor-plugins. There, each command takes a pstack: prefix, such as /pstack:poteto-mode. The Claude Code adapter maps the Cursor names, and a step that needs a Cursor-only feature, such as Bugbot or Automations, is skipped with a one-line note.

This mirror's skills also work in other harnesses (Claude Code, Codex, Pi, OpenCode, and others) through npx skills add backnotprop/pstack. The Harness section of poteto-mode maps Cursor's subagent, question, transcript, and settings paths to the harness's own. Custom Modes are a Cursor feature.

Start a task with /pstack:poteto-mode

/pstack:poteto-mode matches the task to a playbook, copies the playbook's steps into the todo list, and runs the other skills as the steps need them. A step it skips stays in the list as skip: <reason>. A good prompt states the goal and how to tell it's done. It doesn't list skills, because a hand-written sequence tends to drop or reorder steps the playbook would keep. Read references/prompting.md before you help word one. Guide page 2 has examples.

Whether /pstack:poteto-mode stays on depends on how the user starts it:

  • Enter on /pstack:poteto-mode attaches the skill to one message. It fades as the chat moves on.
  • Option+Enter on Mac or Alt+Enter on Windows, or Use as Mode from the skill entry, makes it a Custom Mode. It stays in context every turn until the user exits the mode, and it stays out of casual turns.
  • Cursor's docs list Custom Modes in the Agents Window and the CLI. Elsewhere, start each new task with /pstack:poteto-mode.

Link Cursor's skills docs when this comes up. Mid-chat, "new task" makes the mode match a fresh playbook. /pstack:poteto-mode already uses poteto-agent for the subagents its playbook steps spawn. To get the same style from a subagent of your own, spawn it with subagent_type: "poteto-agent".

The default answer is /pstack:poteto-mode, which runs most of the others when its steps need them. Name a skill directly when the user wants more or less of something than the playbook gives. Read the skill before you recommend it, and give one example prompt.

If a skill directory next to this one is missing from the table, read its frontmatter and route by its description. The principle-* directories are covered under principles below.

Close calls:

  • /pstack:how explains what the code does. /pstack:why explains the reasons. /pstack:teach runs one or both and explains the result plainly.
  • /pstack:arena gives every worker the same brief and merges the best parts. /pstack:swarm splits work into slices or a race and returns one report.
  • /pstack:architect implements right after it settles the design. Add "with checkpoint" to review the design before it writes code.
  • /pstack:interrogate reviews the diff. /pstack:blast-radius looks for breakage outside the diff and proves the one fact that makes the change safe.
  • /pstack:recall rebuilds context across recent chats. /pstack:ketchup covers only this chat since the user's last message. Resuming one specific chat or branch is the Session pickup playbook.
  • /pstack:figure-it-out designs one rigorous run. The Orchestrate playbook runs a program that spans days and many PRs. The Autonomous run playbook drives one task to a finish condition.

Not in pstack:

  • /deslop, control-cli, and control-ui ship in the cursor-team-kit plugin.
  • /loop and /create-skill are Cursor built-ins.
  • pstack has no /orchestrate skill. Orchestrate is a /pstack:poteto-mode playbook. If the slash menu shows /orchestrate, another plugin provides it.

Playbooks and principles

Playbooks are step lists inside /pstack:poteto-mode, not skills, so they have no slash command. Inside /pstack:poteto-mode, describing the task picks one, and these phrases name one directly:

  • "babysit this pr" or "check on pr 123" runs Babysit. It drives the PR to merge-ready and stops there. It doesn't merge unless the user asks to merge, land, or ship.
  • "land the stack" runs Shipping.
  • "take over this branch" runs Session pickup.
  • "pause safely" runs Pause safely.
  • "full autopilot on this queue" runs Autopilot-full. "autopilot, don't merge" runs Autopilot-stack.
  • "run the eval playbook" runs Eval.

Without /pstack:poteto-mode, a phrase such as "babysit this pr" can start Cursor's own skill for the same job instead. The Playbooks section of poteto-mode lists every playbook and when it applies. Guide page 6 covers opening, babysitting, and landing a PR.

pstack has no planning skill. Cursor's Plan Mode works alongside it. For work that spans phases or stacked PRs, asking /pstack:poteto-mode for a plan runs the Multi-phase plan playbook, which writes the plan and doesn't implement it. For a design question, the Prototype playbook or /pstack:architect settles it in code first.

Principles are one-rule skills that /pstack:poteto-mode reads and cites in its replies. The user rarely invokes one. They steer with the names instead, as in "apply prove it works. show me the real output." Typing /principle-<name> still loads one on demand. Guide page 8 lists them.

Fix a run that went wrong

Symptom Fix
The mode stopped applying after a few turns It was started with Enter. Start it as a Custom Mode, or start each task with /pstack:poteto-mode.
A question got treated as the next step of the last task Say "new task", or say the turn doesn't need the mode.
A new model choice had no effect The rule from /pstack:setup-pstack applies to new chats. Start one.
Runs cost more than expected See the cost paragraph under Get set up.
A skill didn't load on its own Only /pstack:setup-pstack loads from the user's words. The others load when the user types them or when /pstack:poteto-mode runs them, and it doesn't run every skill.
Parallel agents overwrote each other Give each agent its own worktree, or run them as cloud agents, which each get their own machine.
An overnight run moved but finished nothing /loop needs a check that can pass or fail, not a duration. See guide page 7.
The reply claims success from a green build Ask for the real command, flow, stored value, or profile. That's the prove-it-works principle.

For a run that drifts, references/prompting.md has one-line steers. Guide page 10 has more pitfalls and the recipes worth copying.

Make pstack my own

  • /pstack:automate-me drafts a personal mode skill from the user's own history, to use alongside /pstack:poteto-mode.
  • /pstack:reflect after a session turns its lessons into skill edits the user approves.
  • /pstack:poteto-mode write a skill for <workflow> runs the authoring playbook. The eval playbook tests a skill change blind.
  • Fix a misbehaving skill in its own PR, not inside the feature work where it went wrong.

Guide page 9 covers each of these.

Reply

Lead with the answer. Give at most one example prompt in a code block, adapted from references/recipes.md when one fits, then the link to that file. Keep it short unless the user asked for the whole map.
