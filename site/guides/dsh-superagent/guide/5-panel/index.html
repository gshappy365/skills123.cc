完整教程约 15 分钟

看懂面板

用「三个问题」把六个标签页串起来，知道每条记录能做什么操作。

面板只回答三个问题

按顺序：现在有需要我的事吗？系统健康、做得对吗？某一件工作从头到尾发生了什么？任何回答不了这三问之一的元素，按设计就该被删掉。

六个标签页

页 回答什么 关键内容
Overview 现在要我做什么 需要人的工单、系统问题、近 24h 计数、执行器负载；每块链到详情页
Source 事件有没有进来 来源状态、安装问题、被过滤的触发与丢弃的消息
Trigger 一条线程里发生了什么 触发（新→旧）、决定、订阅；可按订阅中 / 评估中 / 24h 新增 / 全部筛选
Eval 为什么接或为什么不接 每条决定的理由、命中的规则
Execution 活干到哪了 执行器状态、暂停处理、按阶段筛选的工单；详情里有动作、授权、等待输入、订阅、派工
Settings 怎么改行为 来源、评估、执行、提示词、部署，每组都有保存历史

安装没完成时，Overview 会直接列出缺什么、并链到对应设置，不会让你猜。

你能点的几个动作

动作 作用
Retry 输入投递失败，或工单因报告受阻/失败在等人时重试
Stop 直接作用于工单，记作人工停止，并撤回那份授权
Evaluate again 把某条后续消息重新送去评估，或重试一条没有有效判断的触发
Pause processing 暂停自动处理，但人不受影响
dismiss / unsubscribe 关掉候选卡片、退掉某个订阅
Sync now 重新同步来源那侧的成员名单

读懂几条记录

  • 一条被丢弃的消息会链到它的工单；没有工单就链到线程。Source 页会解释是会话消失了，还是来源不再听它。
  • 仍由某个执行器负责的人工跟进会标成 Delivered to Ticket，旁边写着「没有经过 Eval」——这是订阅扇出，不是新工作。
  • 工单详情显示最初的触发、决定与理由、范围、Policy 版本；结局会写 Pull request merged 或 Stopped by a person。
  • 顶部搜索能按文本、id、飞书消息 id、GitHub 评论链接找触发；也能用 #12 或 GitHub URL 找线程，按标题找工单。

提示词页值得单独说一句

Settings → Prompts 里，Edit 改团队段落和内置部件，Full prompt 展示拼装后的完整文本，History 是版本列表。每一次保存都会生成一个不可变版本（含完整配置、修订号、前身、时间、来源），保存不重启、不取消、也不唤醒会话。

升级后如果你改过的内置默认值变了，那一项会标 Default updated（默认内容已更新），面板把新旧默认值并排放在你的文字上面，让你选「保留我的」还是「用新的」。没被改过的部件会自动跟随新默认值。

几条设计原则，能帮你判断看到的是不是异常

  • 安静是默认状态：健康状态不占空间，一次偶发的网络错误不该变成一个问题卡片。
  • 一个概念只在一个地方：来源状态在 Source，决定在 Eval，工单在 Execution，Overview 只做汇总和跳转。
  • 数字要等于它链过去的列表长度，状态之间不互相矛盾。
  • 标签写「在等谁、等什么」，不写内部状态码。
