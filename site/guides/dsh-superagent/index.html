研究原型 · 非官方中文教程 · 44 篇

让 AI 替团队干活，
但不占用团队的注意力

dsh-superagent 是一份打包给 DeepSeek Harness 的插件：它盯着一个 GitHub 仓库（可选飞书）， 被允许的人 @ 它之后，它开一份工单、在自己的目录里干活、开 PR，然后回到原来那条对话里回你一句。 不主动刷存在感，也不自己合并。

新手三课，20 分钟 我会配置，看完整教程先判断适不适合我

本站不是官方文档。命令与行为以官方仓库为准。

先说清楚三件事

它是研究原型，仓库自己写着「不是 DeepSeek 官方产品、不是生产级软件」；它不是安全沙箱，执行器以你的系统用户身份运行；它更慢更费 token，小改动用它不划算。

你是不是也卡在这里

  • 「改好了，应该没问题了」你一跑还是坏的。来回五轮，一个下午没了。
  • 只想改一个按钮，它动了十几个文件范围没有边界，审起来比自己写还累。
  • 新开一个对话，昨天说过的全忘了同一件事被反复解释，跟进靠人肉记。
  • AI 一活跃，全组都被 @ 醒能替团队干活的助手，也能浪费团队的注意力。

问题通常不在模型不够聪明，而在做事没有章法、也没人管边界。这套东西解决的正是后半句。

装上以后有什么不一样

什么时候普通 AI 助手dsh-superagent
它什么时候在你打开窗口时在一直在：盯着仓库和群，事件来了才动
谁可以让它干活谁都能问，问什么都答只有名单里的人、或团队写下的规则允许时
一件事的记忆这次对话结束就没了从被提出到 PR 合并，一条线程上的讨论都跟得上
怎么算做完说一句「已完成」按影响停止：能评审才交，要决策就停下来问
会打扰谁每条回答都推给你只在有人必须行动或能用上结果时说话
谁合并—人。默认不自动合并，合并是最后一道口子

它怎么干活

  1. 1有人 @ 它在 Issue、评论或群里说清要什么
  2. 2变成一条触发不可变，重复到达也只算一次
  3. 3评估先看名单和规则，再判断这件事值不值得接
  4. 4开工单授权、订阅、派工、确认，一次原子完成
  5. 5自己干独立会话与目录，改代码、跑检查、开 PR
  6. 6回到原对话一个结果，或一个具体问题；你审、你合并

完整链路（含领域模型、评估两层、授权与订阅的边界）在 概念全景图。

新手只要三课

不会写代码也能顺着走完。每课都写了「你应该看到什么」，不对也有地方查。

1它能帮你什么三分钟判断这个值不值得学，以及开始前要准备什么、要付出什么。3 分钟 2装上它用一句话让编码智能体带你完成安装，知道它会问什么、什么时候该你动手。5 分钟 3第一次派活用一句三段式的话把一件小事交给它，并知道屏幕上该出现什么。10 分钟

两条路，自己选

没写过代码从这里开始三课 20 分钟：它能帮你什么 → 装上它 → 第一次派活。只记一句话：要什么 · 怎样算做完 · 给我看什么。进入新手入门 会写代码看完整教程九步：边界与原则 → 环境 → 安装 → 授权 → 第一个任务 → 面板 → 工单生命周期 → 审阅合并 → 升级扩展。进入完整教程

适不适合你

适合
  • 多人协作的 GitHub 仓库，事情在 Issue / PR 里讨论
  • 有人愿意审它交出来的东西
  • 有能长期跑的机器 + 配好模型的 DSH
  • 想省的是「反复解释、来回追问、忘了跟进」
先别用
  • 只有你一个人、只改本地项目
  • 想要开箱即用的 SaaS 产品
  • 用 GitHub Enterprise Server（不支持）
  • 想让它无人值守地刷 PR

拿不准就看 适不适合你，两分钟有结论。

现在就试一句话

装好之后，把下面这段发成一条新的评论（不要编辑已有正文）。尖括号换成你自己的内容。

@<agent login> 请修复 <页面> 在 <条件> 下的 <现象>，补一条回归测试。
做完的标准：<能判断过或不过的条件>，现有测试全绿。
做完请给我：改动前后对比、测试命令输出、改动文件清单。

更多场景在 照抄就能用的请求模板。
