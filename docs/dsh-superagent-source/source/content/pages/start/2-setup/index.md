# 装上它

## 官方推荐的安装方式，是「别自己装」

这个项目的安装步骤很多，所以仓库专门写了一份 `SETUP.md`，**给编码智能体读**。你要做的只是把下面这句发给你的编码智能体：

```
Read SETUP.md in this repository and set up dsh-superagent with me.
```

中文意思：读这个仓库的 SETUP.md，带我一起把 dsh-superagent 装好。

<div class="tu-note tu-note--ok">
<strong>为什么这样更省事</strong><p>它会自己探测环境、一次只问你一个问题、把完整计划一次给你看、你确认后才动手；需要密钥或账号的步骤会整理成一份清单，让你在自己的终端里做，不会在聊天里向你要密码。</p>
</div>

## 它会按什么顺序问你

问题不是随便问的，是顺着一件事流动的方向：**请求从哪来 → 谁可以提 → 干活时用什么**。

| 顺序 | 会问什么 | 推荐回答 |
| --- | --- | --- |
| 1–4 | 只接 GitHub，还是也接飞书？哪个仓库？智能体用哪个 GitHub 账号？飞书接哪些群？ | 先只接 GitHub；账号用专门新建的那个 |
| 5–6 | GitHub 上哪些登录名可以叫它干活？飞书群里谁可以？ | 先只填你自己一个人 |
| 7–9 | 每个工单从哪份本地克隆开工？提交署名用谁？要不要自动合并？ | 新建一份克隆；署名用智能体账号；自动合并先选「不要」 |

<div class="tu-note tu-note--tip">
<strong>一个问题一句话就能答</strong><p>每个问题都带一个推荐答案，回一个字（比如「好」「用默认」）就能过。它每句话不超过 300 词，不会给你念文档。</p>
</div>

## 有默认值的事，它不会来烦你

这些会直接写进计划里，你不用逐项决定：profile 名 `superagent`、面板端口 `3082`、状态目录、分支前缀 `agent/`、`observe` 模式（只记录主动发现的工作，不真的动手）、每小时一次自检、自动合并默认关闭。

## 环境不齐也能开始

探测之后，缺的依赖会被列进计划，而不是变成一串追问。大致是这些（精确版本见 [准备环境](/guide/1-prereqs/)）：

```
Node.js 22.19+ 或 24+ · pnpm · git 2.32+ · tmux
Python 3.8+ · GitHub CLI 2.48+ · 已配好模型的 DSH
```

飞书是可选的，要用才需要 `lark-cli`。如果仓库用了 Git LFS，再装 `git-lfs`。

## 什么时候需要你亲自动手

只有智能体做不到的事：创建智能体专用的 GitHub 账号、接受仓库邀请、用那个账号登录 CLI、在飞书后台创建并发布机器人、填入应用密钥。它会把**确切命令**一次给你，你在自己的终端里跑完，回一句「好了」，它再逐个核对登录身份。

## 你应该看到什么

装完你会拿到三样东西：

1. 一个面板地址（默认 `http://127.0.0.1:3082`），侧栏里的 **Superagent** 就是入口；
2. `scripts/dsh-superagent status` 退出码为 0，没有待处理的安装问题；
3. 一段不超过 300 词的交接说明，包含「从哪里提第一个请求」和三条操作者规矩：**先收窄、把噪音调低、为它说的话负责**。

## 不对怎么办

| 现象 | 大概是什么原因 | 先做什么 |
| --- | --- | --- |
| `status` 退出 1 | 没在跑、或起了两个实例、或没响应 | 看启动日志，别急着重装 |
| 退出 2 | 某个组件报错，重启也修不好 | 按 `errors` 里的具体部件查，别盲目 restart |
| 退出 3 | 还有安装步骤没做完 | 读 `setup` 提示，把缺的账号/配置补齐 |
| 面板打不开 | 端口或 profile 不对 | 确认 `cordis.patch.yml` 里 `port: 3082`，以及用的是 `superagent` profile |

## 别跳过的一步

如果你打算长期跑，请给智能体一个**专用的操作系统账号**。执行器能按绝对路径运行程序、也能读当前用户的家目录；把凭证包装当沙箱用，是这个原型里最容易踩的坑之一。
