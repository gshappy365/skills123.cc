# 它能帮你什么

## 一句话说清它是什么

把它想成**一个住在你仓库里的同事**。你或同事在 GitHub 的 Issue、评论里 @ 它，它就会：

1. 开一份[[工单|Ticket：一件被允许去做的工作，是这套系统里最小的工作单位]]；
2. 在自己独立的会话和目录里改代码、跑检查；
3. 开一个 PR，或者遇到拿不准的事问你一个具体问题；
4. 回到**原来那条对话**里回你一句。

它和聊天窗口里的 AI 最大的区别不是更聪明，而是**它一直在**。GitHub 上发生的事它持续听着；一件事从被提出到 PR 被合并，中间谁来补充、谁来改主意，它都跟得上，不需要你每次重新解释一遍。

## 最要紧的其实不是「能干」

这个项目写在最前面的一句话是：==尽量少占用人的注意力，尽量多给出价值==。

能替整个团队干活的智能体，也能浪费整个团队的注意力。所以它给自己立了两条规矩：

- **只在被点名、或者团队写下的规则允许时动手。**没人叫它，它不会自己找活。
- **只在有人必须行动、或者有结果可用时开口。**接活时确认一次，干活时安静，有结果或需要决定时才再说话。

这也是它和「让 AI 定时刷一堆 PR」这类玩法最不一样的地方。默认的很多保守设置，都是为这两条规矩服务的。

## 开始前要准备什么

| 要准备的 | 说明 |
| --- | --- |
| 一台能长期开着的机器 | 要用 `tmux` 让它在后台持续运行；本机或服务器都行 |
| DeepSeek Harness（DSH） | 它是一份打包给 DSH 的插件，不是独立运行的程序；还要配好模型提供方 |
| 一个 github.com 仓库 | 一个实例对着一个仓库；文档明确说不支持 GitHub Enterprise Server |
| 一个专门的 GitHub 账号 | 它写下的每条评论、每个 PR 都挂在这个账号名下，别用你自己的 |
| 几个命令行工具 | Node、pnpm、git、tmux、Python、GitHub CLI；具体版本在第 1 步 |
| 飞书（可选） | 想让同事在群里直接 @ 它才需要 |

## 要付出的代价

- **更费 token。**它会评估、会自己检查、可能同时跑几份工作，比一次对话贵。小改动用它并不划算。
- **它不是安全沙箱。**执行器和主会话都以你机器上的操作系统用户身份运行，配置里的凭证包装只是「默认用哪个账号」，不是隔离边界。真要隔离，请用只放智能体凭证的专用系统账号。
- **你要为它说的话负责。**它的评论、PR、群消息同事天天看。默认由人合并 PR，就是留了这道口子。

## 先说清楚它不是什么

<div class="tu-note tu-note--warn">
<strong>这是研究原型，不是产品</strong><p>仓库 README 原文写着「仅供研究参考，不是 DeepSeek 官方产品」。它可能有 bug，工程实践也不一定一致，发布版本和团队内部版本、和论文里描述的设计都不完全相同。本站按仓库里公开的文档写成，命令和行为请以官方仓库为准。</p>

它也不是多仓库的团队平台，不是一个能自动合并一切的机器人，更不是「装上就不用管」。

## 你应该看到什么

读完这页，你应该能回答三个问题：它替你做什么、你要准备什么、你愿意承担什么。如果三条里有任何一条现在没法满足，先别急着装，把 [适不适合你](/reference/fit/) 看一眼更省时间。

## 不对怎么办

- **没有 DSH、也没有能长期运行的机器**：可以先只看 [它怎么干活](/reference/flow/) 和 [术语表](/wiki/)，把概念搞清楚，等环境齐了再回来。
- **只想让 AI 写代码给自己看**：这套东西是给「多人 + 一个仓库」设计的，单人用途会显得很重。
