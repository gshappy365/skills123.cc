# 来源 Source

## 一句话

==来源是一条事件流==。一个「种类」是可复用的实现（比如 GitHub），一个「实例」是这份实现的一份具体配置：开不开、听什么。

## 打个比方

像收发室。它决定哪些信件算数、从哪一封开始读（记住读到的位置），把信件按话题分好，并写好回信地址。它自己写的信不往里送，免得自己跟自己对话。

## 在这个项目里

- 保存自己的读位置，所以**重启不会把旧事件重放一遍**；
- 在事件进入领域层之前，先丢掉机器人自己的消息和不属于监听范围的触发；
- 把每条触发翻成它所属的[[线程|Thread：按时间排好的一串触发]]，以及可以回信的[[渠道|Channel：线程的写侧，定义回复地址]]地址；
- 有些条件要等一段时间才成立（比如「某个 CI 连续失败」），这类等待也放在来源里，不让[[评估|Eval：把一批触发变成一个决定]]反过来依赖来源。

仓库里的 GitHub 来源覆盖通知、订阅的 Issue / PR、CI 变化、PR 合并或关闭；可选打开「接收新 Issue / PR / 评论 / 默认分支 CI 的全部事件」。飞书来源覆盖实时事件、历史补齐和订阅话题的轮询。

## 常见误区

- 把它当配置文件或消息队列：其实它负责去重、翻译事件、提供回复地址。
- 以为来源之间身份互通：不同来源的身份**从不互相映射**，那是团队提示词的内容。
