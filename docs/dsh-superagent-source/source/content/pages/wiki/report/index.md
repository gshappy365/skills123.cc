# 报告 Report 与待人工决定 Attention

## 一句话

==报告是派工报给工单的结构化状态==；[[待人工决定|Attention：工单上一个等人回答的结构化具体问题]]是报告里那**一个**具体问题。

## 打个比方

像施工队每天交回的一张表：不是长篇日记，而是「进度 / 卡住 / 完成 / 失败」勾选一格；真需要人拍板时，只写一个问题，附上选项。

## 报告的六种状态

| 状态 | 含义 |
| --- | --- |
| `progress` | 进展 |
| `waiting` | 等待 |
| `ready` | 就绪（绑定 PR） |
| `blocked` | 受阻 |
| `failed` | 失败 |
| `dropped` | 无需处理 |

只有派工的**最终报告**才可能从执行器这一侧结束工单。

## 待人工决定为什么是结构化字段

执行器把**一个**具体问题放进报告，主会话原样转达给人；如果这条问题是由某条消息引起的，就在那条消息所在的地方问，否则回到工单最初的对话。已经获准的工作可以同时继续。

文档明确把「从报告的自由文本里推断『是不是在等人』」列进**被否决的设计**——分类必须用结构化事实，不能靠猜一句话的语气。

## 常见误区

- 把报告当日志文本：它是决定工单阶段的结构化数据。
- 以为它一次会丢五个问题过来：一次一个，而且人下的暂停会一直保持到亲自解除。
