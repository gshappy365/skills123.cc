# 订阅 Subscription

## 一句话

==订阅是工单和线程之间的多对多关系==，由线程持有。匹配到的触发会扇出给每一个还活着的订阅工单。

## 打个比方

像把某条群聊加进「相关」列表：此后群里说什么你都看得见，但看得见不等于有权替群里做决定。

## 在这个项目里

- 扇出时**不检查是谁发的**，也不过准入闸门；但只作为上下文，**不授予新权限**；
- 人发的消息能让已结束的工单在**同一份授权**下恢复，无需评估、无需新决定；
- 机器人和 CI 的消息不会送到已结束的工单（执行器恢复时会重读线程）；
- 被人停掉的工单什么都收不到；
- 只为了看上下文而订阅的线程，不会让工单恢复，也不带来授权；
- 已结束的工单仍保留订阅，包括那条已经关闭或合并的 PR——这样有人在 PR 上再问一句，还能接得上；
- 主会话只在消息**明确指向**工单时才把线程挂上去；「话题相似」不够。

## 常见误区

- 以为订阅会鉴权：授权来自[[授权|Mandate]]，订阅只是投递。
- 以为后续讨论要重新 @ 一遍：不用，同一条线程里的消息会自动送达。
