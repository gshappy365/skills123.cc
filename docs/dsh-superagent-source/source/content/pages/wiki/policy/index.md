# 策略 Policy

## 一句话

==策略是带版本号的规则集合==：哪些规则启用、接单模式是什么、每个来源上谁可以发起工作、名单怎么同步、哪些机器人可以产生候选。

## 打个比方

像公司盖章有效的那版制度。每份[[授权|Mandate]]都记着自己依据的是哪一版；制度改了，新工作按新版办，正在办的活不被硬生生掐断。

## 在这个项目里

- **策略版本**覆盖规则、接单模式和各来源部分；每次改动生成新版本；
- 影响进行中工单的变更（比如它被接单时依据的那条规则改了），会送达该工单的派工，**但不撤销授权、不取消工单**；
- 不同来源的身份**永不互相映射**；
- 接单模式三档：`off` / `observe`（默认，只记录）/ `auto`；明确点名（explicit）的请求三档都生效；
- 提示词里的 `runtime/policy` 段落在每次模型请求时重新生成，放在系统提示最后，这样策略变化不会改动前面的文字；
- 设置保存返回 `restarting: true` 时会重启服务，等 `status` 恢复再继续。

## 常见误区

- 以为消息、评论、引用文档可以改权限：它们只是判断输入，改不了 host 强制的规则。
- 以为策略一改，在跑的活自动作废：不会，那样会留下半完成的工作。
