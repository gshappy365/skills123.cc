# 工单 Ticket

## 一句话

==工单是一份被授权的工作==，只有[[评估|Eval]]能创建它。

## 打个比方

像维修单：从报修到验收都在一张单子上，谁来处理可以换人，单子上的验收标准不变。

## 在这个项目里

- 状态 `open → ended`；人在它订阅的线程上说句话可以再回到 `open`，除非人明确停过它；
- 它**自己定义状态**，不跟随 DSH 会话——所以可以交接、恢复、由好几个[[执行器|Executor]]先后处理；
- 引用它的[[授权|Mandate]]，持有渠道和输入，并记录决定 id；
- 只有派工的**最终报告**才可能从执行器这一侧结束它；
- 结局写成人能读懂的结果，比如 **Pull request merged** 或 **Stopped by a person**。

## 常见误区

| 想法 | 实际 |
| --- | --- |
| 工单就是那个 PR | PR 是结果之一；工单还会继续订阅那条 PR 线程 |
| 会话断了活就丢了 | 工单状态独立保存 |
| 一条线程只能有一个工单 | 可以挂好几个独立工单 |
| 工单状态跟着 Session | 明确被否决的设计 |
