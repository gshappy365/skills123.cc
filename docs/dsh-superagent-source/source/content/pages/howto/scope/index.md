# 别让它顺手动一堆文件

## 请求里就写清边界

一句好请求最多五样东西：**目标、怎样算做完、想看什么证据、你已经知道的、不能碰的地方**。最后一样最常被漏掉。

```
@<agent login> 只改 <文件路径>，其他文件保持原样。
做完请给我：改动文件清单（含每个文件改了什么）。
```

## 跑偏了，一句话

```
不用改别的文件，只处理 <文件>。先把你现在改动了哪几个文件列给我，等我确认再继续。
```

这句会沿[[订阅|Subscription：工单与线程的关系，把新消息当上下文送进来]]送到正在干活的工单，不需要再走一次评估，也不需要新开工单。

## 为什么会顺手动别的文件

执行器读的是仓库原始来源和 `AGENTS.md`，自己判断范围；主会话只做路由，不做技术决定。所以「范围」主要靠你的请求和 `Ticket scope` 段落来约束，而不是靠谁在中间盯着。
