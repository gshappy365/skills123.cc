# 照抄就能用的请求模板

## 好请求的固定骨架

**目标 · 怎样算做完 · 做完给我看什么**，可以再加「你已经知道的」和「不能碰的地方」。别写具体怎么做，也别写你猜的原因。

<div class="tu-note tu-note--tip">
<strong>把 <code>&lt;agent login&gt;</code> 换成安装时定的智能体账号，其余尖括号换成你自己的内容。</strong>
</div>

### 1 · 派一件小事

```
@<agent login> 修复 <页面> 在 <条件> 下的 <现象>，补一条回归测试。
做完的标准：<能判断过或不过的条件>，现有测试全绿。
做完请给我：改动前后对比、测试命令输出、改动文件清单。
```

### 2 · 只要调查，不要改动

```
@<agent login> 先不要改任何代码。把 <模块> 的入口、调用关系、
最容易出问题的两处讲清楚，附上你依据的文件路径。
```

### 3 · 只改文档

```
@<agent login> 把 README 的安装步骤更新成现在能跑通的版本。
每条命令都对照仓库当前脚本核对过；只改 README，不碰其他文件。
做完把改了哪几行贴给我。
```

### 4 · 跟进（不用重新 @ 新工单）

```
把默认超时从 5 秒改成 10 秒，补一条对应的测试。
其他行为保持不变，做完贴出测试输出。
```

后续消息沿订阅送到同一个工单，不用重复背景。

### 5 · 让它停

```
@<agent login> 停一下，这个先不要继续了。
```

人在线程里说 stop 会记作人工停止并撤回授权。

### 6 · 交一份能自己判断的「合同」

```
@<agent login> 目标：<改完是什么样>。
完成标准：<条件 1>、<条件 2>，现有 <行为> 不变。
每做一个决定记一行：时间、决定、理由、证据。
遇到 <具体卡住的情况> 停下来问我，不要自己猜。
做完给我：决定日志、逐条验证输出、改动文件清单。
```

## 还有两句「一句话拉回」

```
不用改别的文件，只处理 <文件>。先把改动清单给我，等我确认再继续。
```

```
这句只要一个具体问题，给我两个选项就行，先别动手。
```
