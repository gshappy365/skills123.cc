# 修一个 bug：先复现，再修，再证明

## 为什么先复现

它默认会「先确认一次、说清接了什么」，但不会自动替你补上「问题到底长什么样」。你写清楚复现条件，它才有办法证明修好了，而不是「应该没问题了」。

```
@<agent login> <页面> 在 <具体条件> 下会 <现象>。
先按下面的步骤让它重现一次，把重现时的输出贴给我，不要先改代码。

复现步骤：<1、2、3>
做完的标准：按同样步骤不再出现 <现象>，且现有测试全绿。
做完请给我：修复前后的实际输出对比、测试命令输出、改动文件清单。
```

## 你应该看到什么

先是一条确认，接着一份复现记录；然后才是改动。PR 描述里带着前后对比和命令输出。

## 不对怎么办

- **它直接改了代码**：回一句「先别改，把复现输出给我」，订阅会把这句送到工单。
- **只说「已修复」没有输出**：别合并，要求补实际命令输出。
- **改了十几个文件**：去 [别让它顺手动一堆文件](/howto/scope/)。
