# 跑偏了，一句话拉回来

## 为什么一句话就够

工单订阅了它起始的那条线程。你在原对话里补一句，这条消息会作为**上下文**扇出给工单，不经过新的评估，也不用重新解释背景。执行器会自己处理属于本工单的跟进；超出本工单的，它会退回去成为新的候选。

## 按现象选一句

| 现象 | 回这一句 |
| --- | --- |
| 动了一堆文件 | `不用改别的文件，只处理 <文件>。先把改动清单给我，等我确认再继续。` |
| 没证据就说做完 | `先别报完成。把 <命令> 的实际输出贴出来，我再看。` |
| 没复现就动手 | `先别改代码。按 <步骤> 让它重现一次，把输出给我。` |
| 问题问得太笼统 | `只问一个具体问题，给我两个选项，先别动手。` |
| 方向理解错了 | `我想要的不是 <它以为的>，是 <你真正要的>。按后者重新确认一次。` |
| 越改越多 | `能删就删。只保留解决 <现象> 必需的最小改动。` |

## 拉不回来怎么办

- 面板上的 `Stop` 会撤回授权，工单不再接收任何消息；
- `Pause processing` 停掉整个执行侧的自动处理；
- 干脆在原对话重新发一条清楚的请求，让它作为新工作进入评估。

<div class="tu-note tu-note--warn">
<strong>别用额外消息解释它为什么跑偏</strong><p>每一条消息都在花团队的注意力。给一句能执行的指令，比给一段复盘更管用。</p>
</div>
