# 补一条回归测试

## 让测试自己证明有效

```
@<agent login> 为 <具体行为> 补一条回归测试。

先让这条测试在修复前跑一次并把失败输出给我，再让它通过。
做完的标准：测试能稳定复现 <那个 bug / 行为>，且全套测试通过。
做完请给我：失败时与通过时两次的真实命令输出、新增文件路径。
```

## 为什么要「先失败」

一条从来没失败过的测试，可能什么都没测到。让它把两次输出都贴出来，你一眼就能判断这条测试是不是真的盯住了问题。这也正好对上它的「诚实交付」规矩：草稿标未完成，没有真实输出不算就绪。

## 不对怎么办

- 只给了通过的输出 → 要修复前那次失败输出。
- 测试改了业务代码 → 回一句「只加测试，不要动实现」。
