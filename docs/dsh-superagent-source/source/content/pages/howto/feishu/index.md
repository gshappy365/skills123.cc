# 加飞书

## 多出来的准备

- 一个飞书机器人应用，需要你在后台创建并发布（这一步是你的，不是智能体的）；
- `lark-cli`，文档提到测过 1.0.90；
- 配置里的应用密钥，在你自己的终端里填；
- profile 的 `cordis.patch.yml` 里把 `dsh-superagent-feishu` 条目的 `disabled` 设为 `false`。

安装时智能体会问「接哪些群」「群里谁可以叫它干活」。群可以按「全部消息」或「仅 @」接收；私信默认开启，也可以关。

## 两个来源的身份不互通

这是领域模型里明确写下的规则：**不同来源上的身份永远不做映射**。GitHub 的允许名单写 GitHub 登录名，飞书写飞书用户 id，两者之间不自动对应。「某个飞书用户其实是哪个 GitHub 账号」属于团队提示词的内容（例如 `identities` 技能），不是一份身份表。

## 你应该看到什么

Source 页出现飞书一行、状态正常；在配置过的群里 @ 机器人，约一分钟内 Overview 出现工单；回复回到原来的群话题里。

## 不对怎么办

- 群里没反应：看群 id 有没有查对、机器人是否已发布、群接收范围是不是设成了「仅 @」而你没 @。
- 私信收不到：检查 `directMessages` 开关。
- 名单同步不对：Settings → Eval → On each Source 里有 `Sync now`，启动时也会同步一次。
