# 加一个小功能，不碰坏旧的

## 关键是把不变的东西说出来

新功能的风险几乎都在旧行为上。你不写，它只能自己猜哪些算「相关」。

```
@<agent login> 给 <模块> 增加 <一句话说清的新能力>。

不能变的：<列 2–3 条现在的行为，例如现有接口返回值、默认配置、无配置时的表现>
做完的标准：<新能力的判断条件>，并且上面几条旧行为逐条仍然成立。
做完请给我：旧行为的验证方式与实际结果、新增测试的输出、改动文件清单。
```

## 你应该看到什么

它会把「不碰坏旧的」当成完成标准的一部分，在交付里逐条给出验证结果。范围之外的文件不该出现在改动清单里。

## 不对怎么办

范围蔓延了，直接在原对话回一句「只保留 <文件>，其他还原」。这比新开一个工单更快——后续消息会沿订阅送到同一个工单。
