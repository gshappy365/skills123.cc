# 怎么让它别自作主张

## 请求层面：三句就够

```
@<agent login> 只做我下面写的这一件事，不要顺手改别的。
开始动手前先复述你理解的目标，等我确认。
遇到需要设计决策的地方停下来问我，不要自己选一个方向继续。
```

它本来就有「确认一次、说清对象与预期结果」「按影响停止，不按努力停止」的规矩；你写出来，等于把这两条从默认行为变成明确的验收点。

## 设置层面：四处一起收

| 位置 | 收什么 |
| --- | --- |
| Settings → Eval → accept mode | 保持 `observe`，主动工作只记录 |
| Settings → Eval → On each Source | 允许名单收窄、准入表别把「名单外 @」设成 explicit |
| Prompts → Ticket scope | 写清什么时候带着草稿停下 |
| Prompts → Delivery requirements | 写清什么才算有证据、可以交付 |

## 一个概念上的边界

外部文本（消息、评论、文档、引用）在系统里**永远只是数据**，不改规则也不改变授权。反过来也成立：你在提示词里写「我有管理员权限」没用，身份和权限是 host 与工具参数强制的。想限制它，改的是设置和请求，不是靠某句话「说服」它。
