# 先只记录，不真的动手

## 默认就是最保守的那一档

`observe` 是安装时的默认接单模式。它照样评估推断出来的工作，但正向结果只记成 `ignore`，理由写「本来会接」（would accept），**不真的开工单**。明确点名的请求不受影响，三种模式下都生效。

## 怎么用这段时间

1. 正常用一两周，别改设置；
2. 到 Eval 页逐条看那些「本来会接」的决定和命中规则；
3. 判断它的判断准不准：该接的漏了吗？不该接的凑上来了吗？
4. 准，再考虑切 `auto`；不准，先改规则或改提示词。

<div class="tu-note tu-note--tip">
<strong>为什么这套设计值得学</strong><p>它把「让智能体主动」这件事拆成了两步：先让它把判断写出来给你看，再由你给它动手的权限。省下的不是 token，是整个团队被无谓 PR 打断的次数。</p>
</div>

## 不对怎么办

- 觉得「什么都没发生」：去 Eval 页看记录，不是没工作，是没接单。
- 忘了自己设过 `off`：Settings → Eval 里看当前 accept mode。
